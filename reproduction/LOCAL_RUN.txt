4. Build the memory-only fallback used for 50 assets
CUDA headers packaged with this local runtime were incomplete, so the C++
source contains the public runtime ABI declarations and enum values checked
against cuda_runtime_api.h and driver_types.h. The ABI was checked against
the installed PyTorch CUDAPluggableAllocator.h.
The actual compilation command was:
  g++ -O2 -shared -fPIC reproduction/managed_allocator.cpp \
    -o reproduction/managed_allocator.so \
    -L/home/jkp/data/limt/.venv/lib/python3.11/site-packages/nvidia/cuda_runtime/lib \
    -Wl,-rpath,/home/jkp/data/limt/.venv/lib/python3.11/site-packages/nvidia/cuda_runtime/lib \
    -l:libcudart.so.12
On another machine use that environment's CUDA runtime library path.

The allocator uses cudaMallocManaged/cudaFree and verifies concurrent managed
memory support. The GPU performs the same FP32 model computations while the
driver pages memory between GPU and RAM. It does not microbatch, change the
loss, use mixed precision or change the optimizer. It has a 10 GiB live-tensor
cap. There is no caching allocator to empty; launch_managed.py makes
torch.cuda.empty_cache a no-op for this process only. Tensor deallocations
already call cudaFree. This execution change is disclosed in the report.
Native and managed allocators produced exactly the same 87 parameter tensors
after four Adam steps in the small-batch engineering check; see
allocator_equivalence.json. Full-batch timing and failed alternatives have
separate logs. A finite comparison is not a proof for all possible inputs.
