# Hermes stock forecasting reproduction

Re-run the independent Hermes model, its ablations and portfolio evaluation.
The S&P 500 implementation uses the released ESTIMATE input panel; NASDAQ and NYSE
companions use the released Temporal Relational Stock Ranking data. This is an
independent implementation with documented data and execution assumptions, not a
claim of exact agreement with every published number. `configs/protocol.json`
contains the frozen main settings.

## Prepare a working directory

Run from this source folder:

```bash
python ../_replication/run.py prepare --project hermes
cd ../.replication-local/workspace/hermes
```

The preparation command copies code into the working directory and links existing
local inputs and the archived environment. Raw inputs are reused, not copied into
this source package. New outputs are written in the working directory. Historical
runs and the previous README are preserved under
`../.replication-local/artifacts/hermes/` relative to this source folder.
Use `prepare --project hermes --reuse-results` to create a working copy of saved
results for replay. To reconstruct prepared inputs from shared raw sources, use
`prepare --project hermes --fresh-inputs` and run the preparation steps below.
When switching from cached to fresh inputs, pass a new `--workspace PATH` so
existing input links remain untouched.
Keep each changed experiment in a separate working directory; retained fingerprints
may reject mixing changed code or settings with old results.

## Environment

Use the linked `.venv/bin/python` when the original environment is available.
For a fresh Python 3.11 environment, run these commands **in the working directory**:

```bash
uv venv --python 3.11 .venv
uv pip install --python .venv/bin/python -r requirements.lock.txt
```

The lock file records the tested versions. GPU runs need a compatible PyTorch/CUDA
installation; installing the environment is separate from running experiments.

## Inputs

The local prepared input files are `data/sp500.npz`, `data/nasdaq.npz`,
`data/nyse.npz` and their manifests. Raw release inputs are under
`upstream/estimate/src/data/US/sp500/` and
`upstream/Temporal_Relational_Stock_Ranking/data/`. These are archive links in the
prepared workspace, not files to publish with this source package.

On a machine without the cached release inputs, obtain the pinned repositories
used by `reproduce.sh`: ESTIMATE commit
`b3e4e100cdb478bdd8803005445102f37926113d` and RSR commit
`cfbb01bdf194b81bc5893a1b37aff1c0d0d2a82d`. Preserve their original licenses.
The recent-period extension also needs shared `crsp-daily/` inputs and historical
security metadata. Its preparation script specifies the exact required columns.

## Run the main experiment

With cached prepared inputs, begin at the tests and training commands. To rebuild
prepared arrays, first run the two preparation commands:

```bash
test -f data/sp500.npz || .venv/bin/python scripts/prepare_data.py
test -f data/nasdaq.npz || .venv/bin/python scripts/prepare_rsr.py
.venv/bin/python -m pytest -q
.venv/bin/python scripts/run_suite.py --device cuda
.venv/bin/python scripts/run_companions.py --device cuda
.venv/bin/python scripts/reevaluate.py --device cuda
.venv/bin/python analysis/no_skip_significance.py
.venv/bin/python scripts/summarize.py
.venv/bin/python scripts/verify_results.py
```

Use `--device cpu` for CPU execution. `HERMES_DEVICE=cpu bash reproduce.sh`
performs the full setup/preparation/run sequence; it can download missing upstream
inputs and synchronize dependencies, so use the explicit commands to reuse an
existing environment unchanged.

The Figure 3 sensitivity suite is separate:

```bash
.venv/bin/python scripts/run_figure3.py --device cuda
```

The recent CRSP extension is `HERMES_DEVICE=cpu bash reproduce_recent.sh`.
It writes its own outputs under `analysis/recent/` and does not replace the
original market experiment.

## Outputs and verification

`results/<run>/` contains selected checkpoints, predictions, configuration and
metrics; summary and verification artifacts are regenerated by the last two
commands. `verify_results.py` checks input hashes and recomputes reported test
metrics. `scripts/predict.py CHECKPOINT --device cpu` replays a saved model.
A short execution check can use `scripts/train.py --output results/smoke --device
cpu --epochs 1`; its metrics are not full-budget paper results.

For month–firm–return exports, `data/sp500.npz` supplies tickers, realization dates,
daily close-to-close returns and the `valid` mask. Compound valid daily returns
within each calendar month; retain missing months rather than treating invalid
returns as zero. The native prediction horizon remains daily.

## Export month–firm–return tables

From this clean source folder, use an interpreter with pandas >= 2.1, NumPy and
PyArrow:

```bash
python ../_replication/month_firm_returns.py --project hermes --data-root ..
```

The exporter reads existing inputs and archived artifacts in place and writes
derived tables under `../.replication-local/tables/hermes/`. Use `--list` to inspect
available market specifications or `--output-root PATH` to choose another output
location. See each table's JSON sidecar for its return definition, coverage and
source paths. Daily-model scores are not represented as monthly return forecasts.
